- **Frontend:** Чистый Vanilla JavaScript (ES6+), HTML5, CSS3 (с CSS Custom Properties, flexbox, CSS-анимациями).
- **Twitch Connection:** `tmi.js` (v1.8.5 CDN) — подключается анонимно (`justinfan`) по защищенному WebSocket (`wss://irc-ws.chat.twitch.tv:443`).
- **Локальные хранилища:**
  - **IndexedDB (`TwitchViewerDB`, версия 3):**
    - `viewers` (keyPath: `username`, индекс: `firstSeen`) — реестр всех когда-либо заходивших зрителей и timestamp первого визита.
    - `profiles` (keyPath: `username`) — кеш профилей зрителей `{ username, fetchedAt, data }` с TTL = 12 часов.
  - **localStorage:** Сохранение пользовательских настроек (канал, лимит ленты, размер аватарки, режим «только новые»).
- **Внешние API:**
  1. **IVR API v2** (`https://api.ivr.fi/v2/twitch/user?login=user1,user2`): Пакетная загрузка данных о пользователях Twitch (до 50 логинов в одном запросе): аватарка, отображаемое имя, фолловеры, дата создания аккаунта (`createdAt`), био, название последнего стрима (`lastBroadcast.title`). Поддерживает таймаут 10s, повторные попытки (retry) и заголовок `Retry-After`.
  2. **TwitchTracker API** (`https://twitchtracker.com/api/channels/summary/{login}`): Получение среднего онлайна зрителей (`avg_viewers`) для стримеров. Таймаут 7s, graceful fallback при недоступности.

## 4. Ключевые механизмы и логика работы

### 4.1. Инициализация и загрузка ассетов
- `index.html` использует встроенный IIFE-загрузчик с `Date.now()` cache-busting для `style.css`, `config.js` и `script.js`.
- Скрипты загружаются последовательно с флагом `script.async = false`, гарантируя, что `config.js` выполнится до `script.js`.

### 4.2. Обработка событий входа и защита от рейдов (`tmi.js` -> `enqueueViewer` -> `processViewer`)
1. При наступлении события `join` имя пользователя приводится к нижнему регистру (`cleanUsername`).
2. **Фильтр ботов (`isBot`):** Сверяется со списком `BOTS` (без учета регистра). Если совпал — событие мгновенно игнорируется.
3. **Буферизация (окно 2 секунды):** Входящие не-боты накапливаются в очереди `joinBuffer` в течение 2000 мс (`RAID_BUFFER_WINDOW_MS`).
4. **Сброс буфера (`flushJoinBuffer`):**
   - **Если количество уникальных заходов в пачке $\ge$ `raidThreshold` (по умолчанию 10):**
     - Фиксируется **наплыв рейда** (`processRaidBatch`).
     - Новые пользователи сохраняются в IndexedDB `viewers` с пометкой `{ username, temporary: true }` **без поля `firstSeen`** (поэтому они не накручивают 24-часовой счетчик новых зрителей).
     - Существующие постоянные зрители не портят свой статус.
     - В ленту `#viewers` выводится **одна компактная карточка рейда** (`showRaidAlert`): `⚡ НАПЛЫВ РЕЙДА: +N зрителей`. Массовые тяжелые сетевые запросы профилей блокируются.
   - **Если количество заходов $<$ `raidThreshold`:** Каждый зритель обрабатывается штатно через `processViewer`.
5. **Индивидуальная проверка в IndexedDB (`processViewer`):**
   - **Временный зритель из рейда (`viewer.temporary === true`):** При индивидуальном повторном визите запись повышается до «настоящей»: флаг `temporary` удаляется, устанавливается `firstSeen = Date.now()`, вызывается `showTwitchUser("ALERT", username, "new")` и увеличивается счетчик «Новеньких за 24ч».
   - **Постоянный зритель (Старичок):** Если включен фильтр «Показывать только новых» (`onlyNewViewers = true`) и пользователь не входит в `COOL_USERS` — событие отбрасывается. Иначе выводится с типом `JOIN` и классом `normal` или `special`.
   - **Абсолютно новый зритель:** Записывается в `viewers` с `{ username, firstSeen: Date.now() }`, обновляет счетчик новых за 24ч и выводится в ленту с типом `ALERT` и классом `.new` (крупный розовый ник `#ff0055`).

### 4.3. Очередь и кеширование данных пользователей (`processVisibleProfiles`)
- **Дебаунс:** Вызовы откладываются на 500 мс (`PROFILE_LOAD_DELAY`), объединяя входящих зрителей в один пакет.
- **Очистка невидимых:** Запрашиваются **только** пользователи, присутствующие в видимой части DOM `#viewers` (если при рейде старые карточки были вытеснены за пределы лимита ленты `viewerFeedLimit`, запросы для них отменяются).
- **Кеш IndexedDB (`profiles`):** Если в кеше есть запись с возрастом `< 12 часов` (`PROFILE_CACHE_TTL`) и заполненным полем `avgViewers`, данные берутся из локальной БД без обращения к сети.
- **Пакетная сеть:** Недостающие пользователи разбиваются на пачки по 50 (`PROFILE_BATCH_SIZE`) и параллельно запрашиваются:
  - Пакетом через `https://api.ivr.fi/v2/twitch/user?login=...`
  - Поштучно через `https://twitchtracker.com/api/channels/summary/{login}`
- Объединенный результат сохраняется в `profiles` и применяется ко всем соответствующим карточкам в DOM.

### 4.4. Анатомия карточки зрителя (`.line`)
```html
<div class="line [new|special|normal|raid] just-added" data-username="alex">
    <div class="avatar [raid-avatar]">
        <img alt="alex" src="..." hidden>
        <!-- Для карточки рейда: <div class="raid-icon">⚡</div> -->
    </div>
    <div class="info">
        <a class="nickname" href="https://twitch.tv/alex" target="_blank" rel="noopener noreferrer">Alex</a>
        <div class="stats">
            <div class="followers">Фоловеров: <span class="count">142</span></div>
            <div class="average_viewers">Зрителей: <span class="count">12</span></div>
            <div class="created_at">Создан: <span class="count">2021.05.14</span></div>
        </div>
        <div class="last_stream">Стрим: <span class="title">Играем в ретро-игры</span></div>
        <div class="bio">Описание канала...</div>
        <div class="datetime">14:20:05</div>
        <div class="type">[ALERT]</div>
    </div>
    <div class="timer-bar"></div>
</div>
```

- **Полоса таймера (`.timer-bar`):** Показывает, насколько недавно зашел зритель. Анимируется через CSS `@keyframes shrink-bar` длительностью `RECENT_VIEWER_DURATION_SEC` (по умолчанию 60 сек). По завершении анимации удаляется из DOM и снимает класс `just-added`.

### 4.5. Счетчик новых зрителей за 24 часа
- Метод `updateNewViewersCount()` выполняет `IDBKeyRange.lowerBound(Date.now() - 24 * 60 * 60 * 1000)` по индексу `firstSeen` хранилища `viewers`.
- Так как временные зрители рейдов не имеют поля `firstSeen`, они игнорируются индексом и попадают в счетчик только при полноценной конвертации.
- Обновляется автоматически раз в 60 секунд, а также с дебаунсом (250 мс) при добавлении каждого нового пользователя, конвертации временного зрителя или очистке базы.

## 5. Конфигурация и настройки

### 5.1. Конфигурация в коде (`config.js`)
```javascript
const MY_TWITCH_CHANNEL = 'fra3a'; // Канал по умолчанию
const BOTS = ['streamelements', 'nightbot', ...]; // Список игнорируемых ботов
const COOL_USERS = ['annacodit', 'fra3a', ...];   // Избранные пользователи
const MAX_LOG_LINES = 50;                         // Дефолтный лимит ленты
const RAID_THRESHOLD = 10;                        // Порог одновременных заходов за 2 сек для детекции рейда
const RECENT_VIEWER_DURATION_SEC = 60;            // Длительность полосы таймера
```

### 5.2. Настройки в интерфейсе (`localStorage`)
Кнопка `⚙️` открывает панель настроек:
- **Канал (`twitchChannel`):** Изменяет канал отслеживания на лету (переподключение TMI `join`/`part`).
- **Показывать только новых (`viewerOnlyNew`):** Чекбокс скрытия повторных визитов обычных зрителей.
- **Порог рейда (`raidThreshold`):** Порог одновременных заходов за 2 секунды (2–100 чел, по умолчанию 10) для включения защиты от рейда.
- **Ников в ленте (`viewerFeedLimit`):** Лимит видимых карточек (1–500), лишние удаляются из DOM снизу.
- **Размер аватарки (`viewerAvatarSize`):** Размер аватарок в пикселях (32–300px), задает CSS-переменную `--viewer-avatar-size`.
- **Кнопка «Сохранить»:** Записывает параметры в `localStorage` и перезагружает страницу.
- **Кнопка «Clear Viewers DB»:** Полностью очищает обе таблицы `viewers` и `profiles` в IndexedDB.

## 7. Правила и рекомендации для AI-агентов

1. **Сохраняйте простоту и легкость:** Проект спроектирован для работы без сборщиков (Webpack, Vite) и без тяжелых фреймворков. Код должен оставаться чистым Vanilla JS, совместимым с современными браузерами.
2. **Безопасность DOM и XSS:** Никогда не вставляйте непроверенные пользовательские данные напрямую через `innerHTML` без экранирования. Используйте `textContent` для текстовых полей (логины, био, заголовки стримов) и `encodeURIComponent` для URL-параметров.
3. **Бережное отношение к внешним API:** Любые новые внешние запросы должны быть снабжены таймаутами (`AbortController`), пакетной обработкой (batching) и кешированием в IndexedDB, чтобы избежать блокировок по IP и превышения rate limits.
4. **Поддержка документации:** После внесения существенных архитектурных или функциональных изменений обязательно обновляйте `docs.md`, сохраняя структуру и актуальность документа.
5. **Тестирование после изменений:** Перед завершением любой задачи обязательно запускайте тестовый набор (`node tests/...`). При добавлении нового функционала дополняйте тесты соответствующими сценариями.
